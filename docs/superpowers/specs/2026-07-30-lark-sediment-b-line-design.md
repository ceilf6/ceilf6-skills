# lark-sediment B 线（叙事语料）设计

日期：2026-07-30。关联：[harness-ceilf6 v2 五项优化](2026-07-30-harness-ceilf6-v2-optimizations-design.md)（收尾沉淀步骤是本篇的宿主）。

## 动机

用户的沉淀目的除了工程知识复用，还有**产出语料**：转正/面试时能讲清楚自己做了什么。现有 A 线门槛（「代码里看不出来」+「别人还会用到」，precision 优先）会系统性排除思维决策类内容——实证：2026-07-30 会话中「方案 A vs B」的取舍被按「已在仓库 spec 里」排除，但个人仓 spec 对评审/面试官不可见。叙事语料需要 completeness 优先、保留决策过程（过程即能力证据），与 A 线「删过程流水账」方向相反，故并行开 B 线而非改 A 线门槛。

## 设计（用户 2026-07-30 两轮口述裁定）

1. **A 线一字不动**：第 1–7 步的门槛、定位、去重、写法规则原样保留。
2. **B 线（叙事语料）**：存在需求上下文（harness `meta.wiki_url` 可取）时，每次沉淀**必产一条**四问叙事节——不做价值筛选，唯一标准是「如实覆盖本轮关键节点」；无需求上下文时 B 线自然跳过。
3. **落点唯一**：A、B 两线同批追加到**同一篇**需求子文档（02-需求 `JhrcwNjUdiUXPMkIUnWcIiOdntc` 下 harness 建的那篇）。B 线不走第 3 步定位、不走第 4 步 `docs +search` 去重。A 线自身「跨需求通用经验另行分类落位」的既有行为不变。
4. **四问模板**（字段对齐 report-writer-bytedance 的 WorkEvent schema：problem / resolution_steps / reflection / sop_candidate，当日新建的飞书文档天然进入日报采集范围，无需改 source-map）：

   ```markdown
   ## 叙事语料（YYYY-MM-DD · 第 N 次收尾）
   - **发现问题**：需求来源与要解决的问题（1-2 句）
   - **解决问题**：2–4 个关键节点，每个写「决策 + 为什么 + 如何验证」（方案取舍、CR 攻防都算节点）
   - **反思问题**：踩坑、书面不采纳的理由、重来会怎么做
   - **总结问题**：可 SOP 化的方法（有则写触发场景+步骤；无则一句话结果）
   ```

5. **增量**：续入后的下次收尾追加新节、只写上次收尾之后的新节点（对照 `sediment.md` 台账与文档内已有叙事节；台账行同样记 B 线）。
6. **写法红线**：保留决策过程但只留关键节点不留流水账；禁空话反思；事实可回链（MR/CR 轮次/commit）。
7. **汇报**：第 7 步汇报中 B 线单独一行（写没写、节标题）。

## 改动清单

- `lark-sediment/SKILL.md`：description 增补 B 线；「配置」节后插入「两条沉淀线」节（B 线定义 + 模板 + 红线 + 增量规则）；第 7 步加 B 线汇报行。
- `harness-ceilf6/SKILL.md`：收尾第 4 步「沉淀」增补一句——同批产出 A 线技术知识与 B 线四问叙事节，两节写入同一篇需求子文档。
- `install-harness.sh`：循环列表加 `lark-sediment`（本次已将 `~/.claude/skills/lark-sediment` 由双拷贝转为 symlink，修复入口须覆盖它）。

## 不做

- report-writer source-map 改动（当日新建文档天然被采集）；lark-recall 配置（根未变）；A 线任何规则调整。
