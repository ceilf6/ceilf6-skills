# 本周期结论

用 2-4 条简洁结论概括结果、主要变化和最值得对齐的判断，每条都能回溯到下方证据。

# 关键进展与证据

按工作线合并重复来源，写清状态、结果和必要的可访问证据链接。证据不足时降低置信度，不把活动等同于成果。

# 做得好的地方

只写有证据的有效做法、闭环或成长信号，并说明为何值得保持。

# 可以优化的地方

每项必须包含：

- 观察依据
- 影响
- 建议改变
- 验证方式

# 需要对齐的议题

Mentor 与 Leader 使用同一份议题清单。每项必须包含：

- 背景
- 希望获得的结果（决策 / 反馈 / 资源 / 优先级 / 知情）

# 上期行动项闭环情况

从唯一的 `Week-(N-1)` 核对完成、进行中、阻塞或无上期基线；不得猜测。

# 本次 One-on-One 待确认行动项

把对齐议题转成可确认的负责人、动作和验证节点，会议前保持“待确认”。

# 下一周期重点

列出 1-3 项与未完成工作、已识别风险或明确优先级相连的重点。

## Publication Rules

- 正文不得出现原始聊天、邮件、AI 对话、浏览历史、终端历史、私有文件内容或本地路径。
- 不展示采集诊断噪声、覆盖 ledger、凭据、token、cookie 或认证信息。
- 不粘贴裸 URL；只对可供 Mentor/Leader 访问且确实支撑结论的企业证据使用描述性 Markdown 链接。
- 不写无证据的绩效、动机、能力、性格或心理状态判断。
